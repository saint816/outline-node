# OutlineNode 0.5.0 GUI 测试与 Bug 报告

测试日期：2026-07-24  
测试方式：在真实 VS Code 窗口中通过鼠标点击、键盘输入、快捷键和 Webview 指针事件进行黑盒测试  
插件：`outlinenode.outline-node` 0.5.0  
环境：VS Code 1.130.0、macOS 15.6.1、Apple Silicon（arm64）

## 结论

当前共记录 5 个问题，其中前 3 个已在本轮 GUI 测试中复现，后 2 个由用户补充、待复测：

- P1：Undo 会跨多个独立结构操作回退，可能撤销用户更早的编辑。
- P2：隐藏完成项快捷键存在焦点陷阱。
- P2：文档末尾代码块后无法继续创建节点。
- P2：代码块节点无法通过 OutlineNode UI 删除。
- P2：粘贴图片后无法在 OutlineNode 中显示。

## 修复状态（2026-07-24，下一版）

| # | 问题 | 状态 | 处理 |
|---|---|---|---|
| BUG-001 | Undo 跨多步回退 | **不复现（已核实）** | 集成测试证明：独立 edit 消息各自成一个 undo step，间隔操作（含报告主场景）单次 undo 只退最后一个。唯一会一起退的是 webview 在 ack 往返前把多 op 批进同一条消息——是单-in-flight 同步协议的固有结果，非缺陷。逐-op undo 需改 echo/ack 协议且会拆散逻辑动作，暂不做。 |

## BUG-001：一次 Undo 会回退多个独立结构操作

严重级别：**P1 / High**  
复现率：**100%（2/2）**  
对应红线：Undo 应由 VS Code 接管，但一次结构操作应形成一步，粒度接近原生编辑器。

### 前置内容

```markdown
- Parent
  - Child
- Tail
- [ ] Another
```

### 复现步骤

1. 在 `Child` 上按 `Cmd+Enter`，将其标为完成。
2. 等待约 1.2 秒，并按 `Cmd+S` 保存。
3. 选中 `Tail`，按 `Alt+↓`，与 `Another` 交换位置。
4. 再等待约 1.2 秒，并按 `Cmd+S` 保存。
5. 按一次 `Cmd+Z`。

### 预期结果

- 只撤销第 3 步的移动。
- `Child` 仍保持完成状态，即 Markdown 中仍为 `- [x] Child`。

### 实际结果

- 移动被撤销。
- 更早的完成状态也同时被撤销，`- [x] Child` 退回普通节点。

另一路径同样可复现：依次对节点执行 `Tab`、`Shift+Tab`，等待后按一次 `Cmd+Z`，无法逐步回到上一个层级状态，多个结构操作被合并在同一个 undo step 中。

### 影响

用户只想撤销最后一步时，会丢失更早且已经保存过的结构编辑或状态修改。该行为不可预测，直接违反项目对 Undo 粒度的验收要求。

### 初步定位建议

推测 `workspace.applyEdit` 产生的多个语义 op 没有形成独立 undo stop，VS Code 将连续的 `WorkspaceEdit` 合并进同一个 undo element。建议重点检查：

- 每条已确认的结构 op 是否需要显式隔离 undo stop。
- `DocumentSession` 连续调用 `workspace.applyEdit` 时的 undo 合并行为。
- 新增集成测试：两个不同结构 op 中间等待并保存，单次 undo 只能回退最后一个 op。

## BUG-002：用快捷键隐藏当前完成项后，快捷键无法再次显示

严重级别：**P2 / Medium**  
复现率：**100%（2/2）**

### 复现步骤

1. 让一个完成节点获得文本焦点。
2. 按 `Cmd+O` 隐藏完成项。
3. 不点击其他位置，再按一次 `Cmd+O`。

### 预期结果

第二次快捷键恢复显示完成项。

### 实际结果

完成项仍然隐藏。点击任意可见节点后再按 `Cmd+O`，才会恢复显示。

顶部工具栏的“隐藏/显示完成项”按钮不受影响。

### 影响

键盘用户进入单向状态：快捷键可以隐藏，却不能立即用同一快捷键恢复。焦点仍留在被 `.hidden` 隐藏的节点上，后续键盘操作也缺少明确落点。

### 初步定位建议

- 隐藏完成项前，如果当前焦点属于即将隐藏的节点，应把焦点迁移到最近的可见节点、搜索框或 Webview 根容器。
- 将全局快捷键监听放在即使 active element 被隐藏后仍能稳定接收事件的位置。
- 增加“焦点位于完成节点 → 隐藏 → 再显示”的 Webview 测试。

## BUG-003：末尾代码块后无法继续创建大纲节点

严重级别：**P2 / Medium**  
复现率：**100%（2/2）**

### 复现步骤

1. 在文档最后创建一个空的顶层节点。
2. 输入 `/code` 并按 Enter，将该节点转换为代码块。
3. 在代码块内输入若干行代码。
4. 尝试通过鼠标或键盘在代码块下方新增一个顶层节点。

### 预期结果

存在明确操作，可以在代码块之后继续创建新的 ListBlock/顶层节点。

### 实际结果

- 代码块成为最后一个 RawBlock。
- 代码 textarea 下方没有“添加节点”入口。
- 在 textarea 中按 Enter 只会增加代码行。
- 快捷键帮助中也没有“退出代码块并在下方创建节点”的操作。

只能切换到内置文本编辑器，手工在围栏代码块之后写入 Markdown 列表，才能继续编辑。

### 影响

用户通过插件 UI 创建末尾代码块后，会被困在文档尾部，无法继续正常的大纲录入。

### 初步定位建议

可以选择一种纯 Markdown 兼容方案：

- 代码块下方提供“添加节点”按钮，创建新的 ListBlock 和空根节点。
- 在 textarea 末行使用明确快捷键（例如 `Cmd+Enter`）在代码块后创建节点。
- `toCodeBlock` 转换末尾节点时保留一个可聚焦的空 `after` ListBlock，但需确认空节点落盘语义，不能破坏 round-trip 红线。

这是文件格式与交互边界问题，确定方案前建议先补 `docs/02`、`docs/05` 和协议说明。

## BUG-004：代码块节点无法删除

严重级别：**P2 / Medium**  
状态：**用户补充，待复测**

### 复现步骤

1. 在空的顶层节点输入 `/code`，将其转换为代码块。
2. 将焦点放入代码块，或尝试选中整个代码块。
3. 使用 Backspace、Delete 或界面中可见的节点删除操作。

### 预期结果

用户可以删除整个代码块及其 Markdown 围栏，而不必切换编辑器。

### 实际结果

OutlineNode UI 中没有可用操作可以删除整个代码块。用户只能切换到 VS Code 内置文本编辑器，手工删除围栏代码块。

### 影响

代码块一旦创建就无法在大纲界面内移除，代码块的生命周期不完整。结合 BUG-003，用户在文档末尾创建代码块后既无法继续新增节点，也无法删除该代码块。

### 初步定位建议

当前 `delete` op 面向 `OutlineNode`，而代码块属于 `RawBlock`；协议中只有编辑代码正文的 `setRawBlock`，缺少删除代码块的语义操作。建议：

- 增加只允许删除围栏代码块的 `deleteRawBlock` 或等价 op，并继续拒绝删除 frontmatter、标题等普通 RawBlock。
- 为代码块提供明确的删除按钮或键盘操作，并加入二次确认或可撤销保障。
- 补充删除头部、中间、尾部代码块后的 Block 合并、round-trip 和 Undo 测试。

## BUG-005：粘贴图片后无法显示

严重级别：**P2 / Medium**  
状态：**用户补充，待复测**

### 复现步骤

1. 将一张图片复制到系统剪贴板。
2. 在 OutlineNode 的节点文本中放置光标。
3. 按 `Cmd+V` 粘贴。

### 预期结果

- 文本中插入 `![[pasted-...]]` 图片引用。
- 图片文件保存到当前 Markdown 文档所在目录。
- 保存完成后，OutlineNode 中显示图片预览。

### 实际结果

粘贴后图片无法在 OutlineNode 中显示。

尚待复测确认以下中间状态：

- Markdown 图片引用是否成功插入。
- 图片文件是否成功写入文档目录。
- `imageSaved` 消息是否返回。
- Webview 重渲染后图片请求是否被 CSP 或 `localResourceRoots` 阻止。

### 影响

用户无法确认图片是否粘贴成功，可能反复粘贴并产生重复图片文件；同时大纲界面与 Markdown 实际内容的视觉状态不一致。

### 初步定位建议

按数据链路逐段排查：

1. `clipboard.ts` 是否正确读取剪贴板中的图片 MIME 数据。
2. `saveImage` 是否只发送一次，文件名和 Base64 数据是否合法。
3. host 是否成功执行 `workspace.fs.writeFile` 并返回 `imageSaved`。
4. Webview 是否把 `![[name]]` 渲染为 `<img>`，资源 URI 是否通过 `webview.asWebviewUri` 转换。
5. `localResourceRoots` 是否包含文档目录，CSP 的 `img-src` 是否允许该资源。

建议增加真实 VS Code 集成测试，断言图片文件只生成一份、Markdown 引用正确，并且 Webview 中的 `<img>` 能成功加载。
